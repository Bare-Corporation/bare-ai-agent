# Bare-AI Todo System

A lightweight, CSV-backed todo manager designed for AI agents. Todos are split
across six small stage files so the AI can find what it needs quickly even as
the backlog grows very large.

## Why split the files?

A single todo file becomes slow to scan as it grows. Splitting by lifecycle
stage means the AI almost always reads only the two "hot" files
(`not_started.csv`, `in_progress.csv`) and touches the rest (`issue`, `on_hold`,
`completed`, `withdrawn`) only when answering occasional user queries.

## Folder contents

| File | Purpose |
|---|---|
| `not_started.csv` | Queued, not begun |
| `in_progress.csv` | Actively worked on |
| `issue.csv` | Blocker / problem needing attention |
| `on_hold.csv` | Parked / waiting on something external |
| `completed.csv` | Done |
| `withdrawn.csv` | Cancelled / no longer relevant |
| `todo.py` | The manager CLI (add, move, list, find, summary, validate) |
| `README.md` | This file |

## Shared header (identical in every file)

```csv
id,title,description,status,priority,created_at,updated_at,due_date,tags,notes
```

| Column | Meaning |
|---|---|
| `id` | Unique short id, generated by the manager (`td-<12 hex>`) |
| `title` | Short task title |
| `description` | Longer description |
| `status` | Lifecycle stage — must match the file it lives in |
| `priority` | `low` / `medium` / `high` / `critical` |
| `created_at` | ISO-8601 UTC timestamp |
| `updated_at` | ISO-8601 UTC timestamp (refreshed on move) |
| `due_date` | Optional `YYYY-MM-DD` |
| `tags` | Optional tags, `;`-separated |
| `notes` | Free-form progress notes |

## Append policy (top vs bottom)

| Stage | Position | Rationale |
|---|---|---|
| `not_started` | bottom | Backlog — oldest first so it is picked up FIFO |
| `in_progress` | top | Focus — newest active task first |
| `issue` | top | Attention — newest blocker first |
| `on_hold` | bottom | Parked — chronological |
| `completed` | top | History — most recently completed first |
| `withdrawn` | bottom | Archive — chronological |

## Usage

```bash
# One-time setup (creates missing files + headers)
python3 todo.py init

# Add a todo (defaults to not_started)
python3 todo.py add "Review council API health endpoint" --priority high

# Move a todo to another stage
python3 todo.py move td-abc123def456 --to in_progress
python3 todo.py move td-abc123def456 --to completed

# List (hot files are fastest)
python3 todo.py list --stage not_started
python3 todo.py list --stage in_progress
python3 todo.py list --json           # machine-readable, all stages

# Find a specific todo
python3 todo.py find td-abc123def456

# Quick overview of backlog size
python3 todo.py summary

# Integrity check (files + headers + status consistency)
python3 todo.py validate
```

## Design notes

- Writes are atomic (temp file + rename), so a partially-written CSV is never
  observed by a concurrent reader.
- The `status` column is kept in sync with the filename on every `move`; a
  row's `status` should always equal the name of the file it lives in.
- `validate` reports any drift (wrong header, or a row whose `status` disagrees
  with its file) so the AI can catch manual edits.
